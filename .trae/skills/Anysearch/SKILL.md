# Anysearch — 外部信息联网核验

对外部信息执行「拆解 → 检索 → 交叉比对 → 十三问审查 → 结构化结论」的核验流程。
检索后端为 AnySearch（`POST https://api.anysearch.com/v1/search`），内置 5 个 API Key 自动轮换（每个每日 1000 次，共 5000 次/天）。

## 触发条件（何时必须调用）

- 任何外部信息输入后需要核实时：新闻、研报、公告、财报、行业数据、他人转述、用户粘贴的网页内容
- 信息中含事实性声明：数字、时间、对象（公司/人物/产品/事件）、产量、产能、订单数量、认证资质、需求、规模等，**包括但不限于**这些类型
- 用户明确要求「核实 / 验证 / 查证 / 联网确认」时

## 执行流程（必须按序执行）

### 第 1 步：声明拆解

通读输入信息，提取所有可核验点，形成核验清单。每个可核验点记录：

- 原文表述（原样引用，不改写）
- 声明类型（数字 / 时间 / 对象 / 产量 / 产能 / 订单 / 认证 / 需求 / 规模 / 其他）
- 核验优先级：关键数字 > 时间 > 对象关系 > 定性描述

### 第 2 步：生成检索式

每个可核验点生成 1–2 条查询词：

- 结构为「主体 + 量化指标 + 时间范围」，如「宁德时代 2025年 动力电池装机量 GWh」
- 中文信息加 `--zone cn --language zh-CN`；涉外信息加 `--zone intl`
- 产量 / 产能 / 订单 / 认证 / 规模类声明，优先构造能命中一手来源（公司公告、年报、监管文件、官方统计）的查询

### 第 3 步：联网检索

用本 skill 的 CLI 调 AnySearch API（Key 自动轮换，无需人工干预）：

```bash
# 基本搜索
python3 <skill_dir>/scripts/anysearch.py search "查询词" --max_results 5

# 中文区检索
python3 <skill_dir>/scripts/anysearch.py search "宁德时代 2025 动力电池装机量" --zone cn --language zh-CN --max_results 5

# 垂直域检索（如金融行情），tag/params 见官方文档
python3 <skill_dir>/scripts/anysearch.py search "AAPL" --tag finance.quote --params '{"type":"stock","symbol":"AAPL","cn_code":""}'

# 查看轮换池状态（key 脱敏）
python3 <skill_dir>/scripts/anysearch.py keys
```

检索纪律：

- 每个可核验点至少取 **2 个独立来源**，单一来源不能定论
- 关键数字必须找到一手来源；只有转载 / 自媒体来源时，该点最高只能给「部分证实」
- 检索结果与声明矛盾时，追加一轮检索排除口径差异（单位、币种、统计范围、时间口径）

### 第 4 步：交叉比对

逐点比对检索结果与原声明：数值、单位、币种、时间口径、统计范围、主体名称是否一致。记录所有差异，即使方向一致。

### 第 5 步：十三问强规则审查（每次核验必须逐条过）

对「原始信息 + 检索证据」整体逐条审查，任何一问不通过都必须在结论中显式标注编号与问题：

| # | 审查项 | 审查要点 |
|---|---|---|
| 1 | 事实是否有来源 | 每个事实性声明能否指认具体来源？无来源即标记「存疑」 |
| 2 | 概念是否被偷换 | 前后「装机量/产量/销量」「营收/收入/GMV」等概念口径是否被悄悄替换 |
| 3 | 推理链是否断裂 | 从证据到结论的每一步是否成立，有无跳步、暗设前提 |
| 4 | 前后表述是否矛盾 | 同一信息内数字、时间、对象是否自洽 |
| 5 | 结论是否超过证据 | 结论的范围、强度是否超出证据支撑范围 |
| 6 | 是否存在反例 | 主动检索反例、相反数据；存在未解释的反例则结论降级 |
| 7 | 是否忽略关键变量 | 价格、汇率、季节性、政策、基数效应等关键变量是否被忽略 |
| 8 | 是否混淆事实与判断 | 「是」与「应该是」是否被混写 |
| 9 | 是否把预测当成确定事实 | 预测 / 预期 / 计划是否被表述为既成事实 |
| 10 | 是否把相关性当成因果性 | A 与 B 同时出现是否被说成 A 导致 B |
| 11 | 是否把局部经验扩大成普遍规律 | 个案、单期数据是否被推广为普遍结论 |
| 12 | 是否把情绪动员包装成理性分析 | 煽动性措辞是否替代了数据与推理 |
| 13 | 是否把立场表达伪装成事实结论 | 利益相关方的观点是否被当作客观事实 |

### 第 6 步：输出核验报告

按以下结构输出（语言跟随用户）：

```markdown
## 核验报告

**核验对象**：<信息来源 / 标题>
**核验时间**：<日期> ｜ **检索来源数**：<N> ｜ **检索工具**：AnySearch

### 逐点核验

| # | 原声明 | 结论 | 证据（来源 URL + 发布时间） | 差异说明 |
|---|---|---|---|---|
| 1 | ... | 已证实 / 部分证实 / 证伪 / 无法核验 | ... | 单位、口径、时间差异等 |

### 十三问审查

- 通过项：...
- 未通过项：<#编号 + 具体问题>

### 总体结论

<信息整体可信度；未被证据支撑的部分；剩余不确定性；建议追加核验的点>
```

## API Key 轮换机制

- Key 池：5 个 key 存于 `<skill_dir>/.env`（`ANYSEARCH_API_KEYS`，逗号分隔），每个每日 1000 次
- 脚本自动 round-robin 轮换 + 每日计数；超限或 401/402/429 自动切换下一个 key 重试，调用方无感
- 轮换状态存于 `<skill_dir>/.rotation_state.json`，按日自动重置
- `.env` 已被 workspace `.gitignore` 覆盖：**绝对不能 commit / 截图 / 外传**
- 单 key 需求可用环境变量 `ANYSEARCH_API_KEY` 或 `--api_key` 覆盖轮换池

## 降级与边界

- **全部 key 用尽**：脚本自动降级为匿名调用（低限额）；仍失败则告知用户「今日额度耗尽，可次日再试或经确认后回退其他搜索方式」
- **敏感信息**：查询词与 URL 会发送至 api.anysearch.com —— 密码、个人隐私、商业机密不得作为查询词
- **检索不可用**（网络 / 服务故障）：明确告知用户未能联网核验，相关结论必须标注「未核验」
- **核验不等于背书**：即使全部证实，也只说明「与当前公开来源一致」，不等同于绝对真实；注意来源的时效性

## 参考

- `--max_results` 范围 1–20，默认 10；核验场景建议 5，控制上下文长度
- API 响应结构：`data.results[]`（title / url / snippet / content）+ `data.metadata`（total_results / search_time_ms）
- 官方文档：https://www.anysearch.com/docs
